stockdb 策略开发技能 · 完整使用说明书

版本 v2.4.0 ｜ 适用 stockdb 本地行情库（stockdb.exe 监听 127.0.0.1:7899） 定位 从「本地行情库」到「选股策略」再到「策略看板」的端到端开发手册 读者 使用本技能的人（SKILL.md 是给 agent 的运行时路由，本文件是给人的完整手册）

第 1 章 认识这个技能

1.1 一句话定位

在本机的 stockdb 行情库上，用受验证的取数协议批量拉全市场日 K， 写筛选条件与评分模型，产出结果集 + 报告 + 离线看板，并有自检兜底。

1.2 能力边界

✅ 能做 ❌ 不能做
全市场日 K / 分钟 K / 复权 / 周月 K 批量取数 真实筹码分布（需外接数据源，本地只有近似）
技术指标（MACD/KDJ/RSI/BOLL/MA）批量计算 财务三表、因子、资金流（在线接口，有配额）
板块映射（股票 ↔ 板块） 跨时点比较筹码（近似值只在同一时点可比）
任意条件选股、评分排序、漏斗计数 交易下单、实时行情推送
单文件离线看板（含图表、下钻、组合构建） 回测框架（本技能不提供收益回测）

1.3 什么时候该用它

触发词：stockdb、7899、本地行情库、gp.js、stock_sdk、rd.vals、rd.get_data、 zb.get、bk.get、选股策略、条件选股、策略页面、策略看板、全市场筛选、 筹码分布、主力洗盘、拉升前夜、换手率排名、连续涨停、批量取日K

典型请求：

  • 「帮我写一个选股条件，找出主力洗盘后即将拉升的股票」
  • 「用本地数据库把全市场日 K 拉下来」
  • 「做一个策略结果看板页面」
  • 「这几个条件筛选一下，再按 XX 排序」

1.4 三条铁律（违反必出问题）

  1. 取数走 rd 通道（裸 HTTP 或 Python stock_sdk.rd）——不要用 gp.js。 那个有授权门禁，Node 下必抛 SDK校验失败。裸协议与 Python SDK 都无门禁。
  2. 全市场用「代码前缀 × 日期区间」，4 个请求取回整段历史。 不要写按日循环、不要写代码分片。
  3. 策略只用本地通道（rd / zb / bk / rd.get_data）。 财务、因子、资金流、get_price 是在线接口、有配额，批量取数会失败。

第 2 章 环境准备

2.1 stockdb 是什么

一个单机运行的 A 股行情数据库，把历史日 K / 分钟 K / 复权数据装进本地 LevelDB， 通过一个 HTTP 服务对外提供查询。免密、离线、无限量。

<stockdb 目录>/
├── stockdb.exe          开库 + 起 HTTP 服务（监听 127.0.0.1:7899）
├── 数据更新.exe          从上游同步最新行情
├── data/  data1/         LevelDB 数据（合计约 25 GB）
├── mydb/                 私有数据区（写因子/缓存只能写这里）
├── stockdb.conf          配置（含端口）
└── 调用方式/
    ├── http/            裸 HTTP 示例（rd_test.py）
    ├── python/          ★ Python SDK（stock_sdk）+ 最权威接口文档（1672 行）
    ├── ai_自动开发文档/   JS 侧规则与口径文档
    └── ai_mcp/          MCP 服务（41 工具，多数包在线接口）

路径因机器而异，不要硬编码。本机参考路径：D:\baidunetdiskdownload\stockdb

2.2 启动顺序

# 1) 先同步数据（可选，看你要不要最新交易日）
"<stockdb>/数据更新.exe"

# 2) 再开库（必须，否则 7899 连不上）
"<stockdb>/stockdb.exe"

2.3 连通性自检

一次调用同时验证「服务在线 + 数据可用 + 取数语法正确」：

curl -s "http://127.0.0.1:7899/?cmd=vals&t=%E6%97%A5k&k1=all:&k2=key:20260930&json=1" | head -c 200

预期返回一个对象数组。若返回：

返回 含义
{"error":"only get/vals/keys/len/reload commands supported"} 服务在线，但 cmd 拼错了
空 / 连接拒绝 stockdb.exe 没启动
乱码二进制 漏了 &json=1
[] 语法错（多半是把通配符塞进了冒号链），见 §4.2

2.4 三种接入通道怎么选

通道 门禁 适合 本技能用法
裸 HTTP 无 Node 脚本、浏览器直连、快速验证 ★ 默认，scripts/fetch_all.js
Python SDK 无 已在 Python 环境、要指标/复权 ★ 默认，scripts/fetch_all.py
gp.js（JS SDK） 有 — ❌ 不要用，Node 下抛 SDK校验失败
MCP（41 工具） 无 交互式探索 ⚠ 多数包在线接口，批量取数不要走它

2.5 依赖要求

组件 要求 说明
Node ≥ 18 脚本零第三方依赖，只用 http/fs/path
Python 3.12+ 需能 import stock_sdk（把 pybao/ 加进 PYTHONPATH 或设 PYBAO）
浏览器 现代 看板是单文件 HTML，双击即开

Python SDK 的引入方式：

import sys; sys.path.insert(0, r'<stockdb>/pybao')   # 或设环境变量 PYTHONPATH / PYBAO
from stock_sdk import rd, zb, bk                      # 无授权门禁

第 4 章 取数协议（核心）

4.1 键结构

日 K 表的键是两段式：表:key1:key2 = 日k:代码:日期。

❗ 不要把通配符塞进冒号链。 t=日k:*:20260930 会返回 []。 通配要用 k1 / k2 参数表达。

4.2 k1 / k2 算子表

算子 语义 例子
all: 该段全匹配 k1=all: = 全部代码
key:X 精确匹配 k1=key:000001
qz:X 前缀匹配 k1=qz:6 → 6 开头全部
fwd:a,b 正区间（含两端） k2=fwd:20260325,20260930
fwd:a,N a 起至最新 k2=fwd:20260901,N
fwz:a,b 同区间反序 —

💡 qz: 本身就带「前缀」语义，所以尾部的 * 要剥掉：写 PREFIXES=0*， 拼 URL 时转成 k1=qz:0（不是 qz:0*）。

4.3 ★ 批量取数首选写法

BASE=http://127.0.0.1:7899

# 前缀 × 日期区间：每个前缀 1 个请求，覆盖该前缀全部票的整段历史
GET /?cmd=vals&t=日k&k1=qz:0&k2=fwd:20260325,20260930&json=1     # → 193,204 条

其他常用形态：

GET /?cmd=vals&t=日k&k1=all:&k2=key:20260930&json=1              # 全市场单日
GET /?cmd=vals&t=日k&k1=key:000001&k2=qz:202609&json=1           # 单票某月
GET /?cmd=keys&t=日k&k1=key:000001&k2=all:&json=1                # 键名（推交易日历）
GET /?cmd=get&t=股票代码&json=1                                   # 元数据

&json=1 必须加，否则返回 LevelDB 二进制。

4.4 性能：三代演进（均实测）

方案 请求数 耗时 记录 股票池
交易日 × 50 代码分片 19,500 11.0s 972,846 5184
交易日 × k1=all: 130 8.1s 973,580 5186
前缀 × 日期区间 4 7.2s 713,338 5494

⚠ 早期版本的错误结论（已作废）：「不能一次取全市场某日，只能按代码分片 × 按日循环」。 这个错判导致 fetch_all.js v1 写了二维分片、19,500 次请求。v3 只要 4 次。 如果你看到任何文档写「全市场重算 = 19630 请求、务必 CHUNK=50 + 并发 6」，那是 v1 遗留。

区间可以很长：实测 0* 前缀单请求取 2020-01-01 ~ 2026-09-30 → 2,409,141 条 / 4.7 秒。

不需要并发：服务是本机单进程 LevelDB，v3 只有 4 个请求，串行即可。

4.5 ★ 返回体字段名（高频事故点）

cmd=vals 默认返回具名对象数组，字段是全名：

[{"code":"300870","date":20200824,"open":75,"high":97.65,"low":66.26,"close":85,
  "pre_close":25.446,"volume":13003363,"amount":993162048,"turnover":54.1915,
  "pct_chg":130.916,"amplitude":85.28,"float_share":23995199,
  "float_mv":1455783413.189,"total_mv":6139781604.426,"total_share":101200000,
  "name":"欧陆通","is_st":false,"pe_ttm":53.918313,"pb":15.840099,
  "vol_ratio":null}, ...]
要点 说明
字段是全名 date/open/high/low/close/volume/turnover/name/is_st
date 是数字 20260930，不是 "2026-09-30" → 展示前要格式化
name / is_st 自带 不必另开接口查名称
位置数组只在 ap= 投影时出现 默认不要按数组解

❗ 高频事故：页面/脚本里写 r.c、r.d、r.v 取字段 → 全部 undefined， 图表静默变空白或显示 undefined，而语法检查不报错。 实测踩过：烛台图显示 undefined → undefined，node --check 与自检全绿。

稳健写法（兼容数组 / 短键 / 全名三种形态）：

const pickf = (r, ...keys) => { for (const k of keys) if (r[k] != null) return r[k]; return undefined; };
const norm = (r) => Array.isArray(r)
  ? { d: r[0], o: +r[1], h: +r[2], l: +r[3], c: +r[4], v: +r[5] }
  : { d: pickf(r,'d','date'),  o: +pickf(r,'o','open'),   h: +pickf(r,'h','high'),
      l: +pickf(r,'l','low'),  c: +pickf(r,'c','close'),  v: +pickf(r,'v','volume') };

✅ 交付前必须截图验真（见 §7.6）。fetch_all.js 落盘的 kline.json 用的是短键 （{d,c,pc,o,h,l,v,a,to,p,am,st,fsh,fmv,n}），和接口返回的全名不同 —— 两者都要小心。

4.6 通道边界：本地 vs 在线

通道 内容 额度
✅ rd.get / vals / keys / pipe 日k 分钟k 复权 股票代码 退市 本地、无限量、可离线
✅ rd.get_data(...) 真复权（fq='qfq'/'hfq'/None）、周/月 K（frequency='1w'/'1M'） 本地
✅ zb.get(...) 批量技术指标 macd/kdj/rsi/boll/ma 本地
✅ bk.get(...) 板块映射（股票↔板块，含成分股） 本地
❌ get_price get_bars get_trade_days get_all_securities 结构化行情 在线，有配额
❌ alpha get_factor_values MACD KDJ 因子 / 指标 在线
❌ get_money_flow get_mtss get_billboard_list get_locked_shares 资金 / 事件 在线
❌ valuation income balance cash_flow indicator macro 财务 / 宏观 在线

在线接口失配时不返回数据，且两种形态都要检查：

'测试期超2000次，…'      # ① 配额提示字符串
{'error': '…'}          # ② 业务错误字典 ← 不一定抛异常！

👉 写策略一律只用本地通道。 官方要求：批量历史行情必须用本地 stockdb.exe + rd。

4.7 三个本地加工接口（不要自己手搓）

官方规则：复权 / 周月 K / 分钟聚合必须用 rd.get_data()。

kd     = rd.get_data(['000001'], start='20260101', end='20260930', frequency='1w', fq='qfq')
macd   = zb.get('macd', kd)          # 复用已加载行情，不再访问数据库
boards = bk.get('000001')

⚠ zb.get 两个陷阱： ① 只传 codes 不传 end → 默认只算 20260302 那一天； ② 传 original 时 start/end/frequency/fq 失效，且不接受无列名的位置矩阵（须 fields=None）。

4.8 Python SDK 速记

QueryResult 方法 返回
.do() list[dict] ← 要 dict 就用这个
.vals() list[list] —— 纯数组、无字段名（照 dict 解析会静默全 0）
.keys() 字段名
.url() 反查等效 HTTP ← 学语法最快的办法

服务端参数（在服务端执行，别下载后再处理）：

写法 转成 HTTP 效果
q[:N] / q[-N:] &num=N 切片（-N 取最新 N 条）
q.get('a,b,c') &ap=get.a,b,c 投影（返回位置数组，不是 dict）

4.9 私有数据硬约束

因子 / 缓存 / 策略结果必须用 rd.set() / rd.pipe().mset() 写进 ./mydb。

❌ 严禁自建 SQLite / MySQL / DuckDB / Parquet —— 官方列为「严重错误」。 批量写入必须走 pipe。

第 5 章 标的池

5.1 前缀法本身就是纯股票池

0* + 3* + 6* + 920* —— 1* / 5*（基金/债券/ETF）根本取不到。

前缀 覆盖 实测只数
0* 深主板 / 中小：000 / 001 / 002 / 003 1488
3* 创业板：300 / 301 / 302 1395
6* 沪主板 + 科创板：600/601/603/605 / 688/689 2303
920* 北交所（老段 43x/83x/87x 已迁移） 308
合计 5494

ETF / 基金 / 转债零污染，无需事后正则过滤。科创板默认保留；302 是创业板新增段，别漏。

5.2 兜底正则（仅在数据源变化或误用前缀时才需要）

if (/^(159|16[0-9]|18[0-9]|50[0-9]|51[0-9]|52[0-9]|55[0-9]|56[0-9]|58[0-9]|11[0-9]|12[0-9]|204|900)/.test(code)) return false;
if (/ETF|LOF|REIT|基金|转债|债/i.test(name || '')) return false;

❗ 绝不能写 9[0-9]{5} —— 9* 段实测 308 只全是 920xxx 北交所、B 股 0 只。 那会整段误杀北交所（本技能曾犯此错，修复后命中数 C1 90→92、C2 47→46）。 B 股只有 900xxx。

5.3 限定板块子集

用前缀白名单，绝不要加 $：

function boardOf(code) {                    // ← 不要写成 /^(300|301|302)$/
  if (/^(300|301|302)/.test(code)) return '创业板';
  if (/^(600|601|603|605)/.test(code)) return '沪主板';
  if (/^(000|001|002|003)/.test(code)) return '深主板';
  return null;                              // 688/689、920 等 → 不收
}

❗ 策略池变成 0 只 ⇒ 第一个怀疑这个正则的 $。 实测踩过：加了 $ 后 /^(300|301|302)$/ 匹配不到 300001，5494 只被全部剔除。

5.4 改过滤规则的铁律

过滤规则改动会静默改变选股结果。 改完必须：

  1. 重跑并对比命中数变化；
  2. 跑 selftest.js 第 9 组（专门拦「某板块被整段误杀」）。

第 6 章 写一个策略

6.1 换策略的标准动作（4 步）

  1. 新建项目目录，把需要的脚本复制过去再改 —— 不要原地改技能文件；
  2. 条件段整段替换（不是改阈值），CFG 按新策略重写；
  3. 换策略族必读 references/strategy-variants.md 重标评分方向，不照抄示例权重；
  4. 样例值（days=3、maxGain=7、minChip=70）只是能跑通的默认值，不代表任何推荐。

📌 技能里没有「写死的策略」。 screen.js 自带的「三条件 · 洗盘拉升」是样例， 不是技能在推行这个策略。骨架（取数以外）才是复用价值：标的池过滤、筹码近似、 评分框架、输出契约、漏斗计数。

6.2 换策略族 = 重新设计，不是调参

有些维度方向直接相反：

维度 洗盘拉升 超跌反转
均线状态 要粘合 剔除粘合（<5% 直接淘汰）
换手率 要活跃 要死寂（0% 才满分）
位置 区间 25~75 分位（中位最佳） 越低越好（破 MA120 达 10%+）
量能 要抬头 要创新低

方向互斥必须显式处理：不能靠「权重调小」兼容，必须换掉该维度的计分函数 （或直接改成排除条件）。

6.3 重标定四步法

第 1 步 · 写清「收益来源」一句话（不能是"找好股票"）：

  • 洗盘拉升：「主力已控盘、洗盘充分、即将脱离成本区」
  • 超跌反转：「抛压枯竭、价格远离长期均值，存在回归动能」

这句话决定后面所有维度的正负号。

第 2 步 · 每个维度定成「越大越好」

统一方向后加权求和才有意义（否则正负维度会互相抵消）。

第 3 步 · 只设「单侧阈值 + 线性映射」

const clamp = v => Math.max(0, Math.min(100, v));
const linear = (v, zeroAt, fullAt) => clamp((v - zeroAt) / (fullAt - zeroAt) * 100);
const shrink = linear(1 - volRatio20, 0, 0.5);     // 量比 1.0 → 0 分；≤0.5 → 满分

⚠ 不要用多段阈值：分档会制造人为断点，同一只票差 0.01 就掉档，排序出现跳变。

第 4 步 · 权重按「收益来源的因果距离」分配

离收益来源越近的维度权重越高。若把「止损空间」设成 30%，模型会专挑 「跌得浅但止损远」的票，与策略意图背离。

6.4 条件写法族（可直接组合）

需求 写法要点
连续 N 日上涨 close[i] > close[i-1] 且 pct_chg > 0（双条件，防除权日误判）
累计涨幅 (last.close - first.pre_close) / first.pre_close —— 用首日 pre_close，否则少算第一天
温和上涨 连涨序列中排除涨停日，否则「≤7%」形同虚设
缩量 / 放量 近期均量 / 基准均量，基准取 20 日
均线粘合 (max(MA5,MA10,MA20) - min(...)) / MA20 < 阈值
位置分位 (现价 - 区间低) / (区间高 - 区间低)；<0.25 低位，>0.75 高位
换手排名 先全市场算和排序取前 N，再叠加其他条件。顺序反了会漏
新高 / 新低 注意 >= 与严格 > 会差一只
上市天数 窗口内记录数近似。不要拿首条记录日期当上市日

6.5 涨停判定的三种口径

// ① 用 close/pre_close 反推（最可靠，能处理 ST）
pct = (close - pre_close) / pre_close * 100
涨停 = pct >= 阈值 - 容差

// ② 直接用 pct_chg 字段（省事，除权日可能失真）

// ③ 按板块推断阈值
主板(60/000/001/002/003) 9.8% ｜ 创业/科创(30/68) 19.5%
北交所(4/8/92) 29.5%       ｜ ST 4.7%

容差 0.3% 不是可选项 —— 四舍五入会让「9.99%」偶尔小于 10%。

⚠ ST 的 5% 缩窄只发生在主板。创业板 / 科创板 ST 仍是 20%。 无条件套 isST && pct >= 4.7 会把创/科 ST 股 5% 的普通上涨误判为涨停，虚增涨停数。 正确写法：boardOf(code)==='main' && isST(row) && …

⚠ 上市 5 日内不限价，会把大涨幅误判为涨停。用 minListDays ≥ 30 自然规避。

排除 ST 要双验证：is_st === true 且名称含 ST（历史记录里 is_st 偶有缺失）。

6.6 获利筹码近似

本地没有真实筹码分布，用成交量加权近似：

TP_i = (High+Low+Close)/3               典型价
w_i  = 1 - (日龄/窗口) × 0.6            时间衰减 ← 不可省
V_i  = Volume_i × w_i
获利筹码 = Σ{V_i | TP_i ≤ 现价} / ΣV_i × 100%
集中度   = 1 - 加权标准差 / 加权成本
窗口     = 90 交易日

三条纪律：

纪律 理由
必须加时间衰减 不加则单边上涨股恒 100%（银行/公用事业），排序失去区分度。decay=0.6 是实测甜点
必须标注为估算值 写进页面和报告的注释里
只做同时点横向排序 不可跨时点比较，不可当绝对买卖阈值

局限（要写进交付物）：无法识别同价位多次换手 → 高估长期横盘股；未单独处理送转除权。

💡 何时该换真数据：局部需要精确筹码时，外接真实筹码分布数据源（含同价位换手叠加）。 本技能的近似用于全市场粗筛 —— 五万次近似计算在本地 0.1 秒完成，外接接口做不到。

6.7 ★ 排除类条件：先验证它「有没有在起作用」

排除条件比入选条件更容易静默失效 —— 参数配了、流程跑通、有输出，但一只都没剔掉。

必做动作：每个排除条件都记数，跑完打印。

const rejCnt = {};
for (const r of rejected) for (const x of r.reasons) rejCnt[x] = (rejCnt[x]||0) + 1;
console.log(Object.entries(rejCnt).map(([k,v]) => `${k}×${v}`).join(' / '));

判别表：

现象 判断 处置
剔除数 = 0 阈值与候选池分布完全不重叠 条件对本策略族不适用 → 标注「未生效」
剔除数 ≈ 候选池全部 阈值过松 改分位法重定阈值
剔除数 = 1~2 阈值落在分布极端尾部 改用分位法
剔除数 ≈ 候选池 10~30% 健康 保留

实测教训（超跌反转，318 只候选）：

条件 原设阈值 实际剔除 结症
获利盘 > 70% 70% 0 只 候选池获利盘中位仅 6.3%、最高 48.9% —— 深度破 MA120 的票持仓者几乎全亏
筹码集中 > 绝对阈值 0.62 1 只 conc = 1-σ/μ 实测分布压在 0.56~0.97、中位 0.89

❗ 不许"偷偷放宽阈值凑数"。 用户给了「剔除获利盘 > 70%」，实测一只不剔就改成 30% 让它剔掉 45 只 —— 用户会以为自己要的那条在过滤，实际逻辑已被换掉。 正确做法：原样保留阈值，在报告/页面写「本批未触发 + 原因」， 若要改口径，先向用户提议并确认。

σ 归一化类指标（1-σ/μ、变异系数、Sharpe、离散度）的阈值必须取当期分布分位 （如 90 分位），不能拍绝对值 —— 这类指标分布既被压缩、又逐期漂移。

6.8 ★★ 评分维度：先算「方差贡献」，别让权重变成摆设

与 §6.7 是同一个病，但在加分侧：排除条件是「剔不掉任何东西」， 评分维度是「几乎全员满分」—— 权重写了 30%，实际影响可能只有 1%。

交付前必做：对每个维度算 满分占比 与 对总分的方差贡献。

const fullRate = rows.filter(r => r.scoreParts[k] === 100).length / rows.length;
const share = varOf(rows.map(r => r.scoreParts['w' + K])) / varOf(rows.map(r => r.score));
指标 健康区间 危险信号
单维满分占比 20% ~ 45% > 70% ⇒ 该维几乎无区分度
单维方差贡献 与权重同量级 < 权重的 1/5 ⇒ 权重是摆设

实测（超跌反转，93 只命中，权重 缩量40 / 箱体30 / 获利盘30）：

维度 初版锚点（拍绝对值） 满分占比 方差贡献 改分位锚点后 改后贡献
缩量 40% 量比 ≤ 0.50 满分 71.0% 62.3% 41.9% 77.2%
箱体低位 30% 天然 0~1，无需锚点 3.2% 51.0% 3.2% 5.4%
获利盘 30% 获利盘 ≤ 20% 满分 92.5% 1.3% ← 摆设 25.8% 28.6%

总分极差从 28.8 分拉开到 82.8 分。

根因：命中池是已经被硬条件筛窄的子集。条件含「量创 20 日新低」→ 池内量比天然 <0.5； 含「深度破 MA120」→ 池内获利盘天然很低。 在筛窄后的池里用「看起来正常」的绝对锚点 → 必然饱和。

解法（照抄）：

const qOf = (a, q) => { const s=[...a].sort((x,y)=>x-y); return s[Math.floor(s.length*q)]; };
const P = qOf(poolVolRatios, 0.25),  Z = qOf(poolVolRatios, 0.75);   // 缩量：25分位满分 / 75分位零分
const CP = qOf(poolChips,      0.25), CZ = qOf(poolChips,      0.90); // 获利盘：25分位满分 / 90分位零分
const lin = (v, full, zero) => Math.max(0, Math.min(100, (zero - v) / (zero - full) * 100));

锚点要落盘到 meta.scoring.anchors，让结果可复现、页面不用复刻算法。

6.9 排序主键 ≠ 评分：两者都要时怎么办

用户可能同时给两条看似冲突的要求：「按离 MA120 越远排序」+「缩量40/箱体30/获利盘30 评分」。 不是二选一，是分主次：

kept.sort((a, b) => (a.dev120 - b.dev120) || (b.score - a.score));
//                   ↑ 主键：用户明示口径        ↑ 次键：同深度比质量
  • 已用作主排序键的因子不要再计进评分（否则同一含义被计两次 → 双重加权）；
  • 页面同时提供两种排序按钮，让用户能切换验证。

6.10 「零共振」是正常结果

不同条件刻画不同阶段：温和连涨 ↔ 高换手 ↔ 涨停基因，本就互斥。

遇到零共振时：

  1. 报告双条件共振清单（通常 20 只上下）；
  2. 说明互斥原因；
  3. 让用户自行选一条条件深挖。

不要为了凑数放宽条件。 这是策略特性，不是 bug。

附录 A 踩坑全记录

这些是实际付出过代价的坑，按危害排序。

A.1 三个高频既踩之坑

坑 症状 纪律
*/ 写在 /** */ 块注释里 SyntaxError: Invalid regular expression flags 注释里写前缀列表一律用顿号：0*、3*、6*、920*。已在 fetch_all.js、screen.js 复发多次
代码前缀正则加了 $ 锚尾 /^(300\|301)$/ 匹配不到 300001 → 策略池整个变 0 只 前缀匹配绝不要 $。池子为 0 时第一个怀疑这里
σ 归一化类指标用绝对阈值 条件"配了但只剔掉 1 只" = 等于失效 必须取当期候选池分位

💡 关于第二个坑的一个次生教训：单测时手工把正则抄一遍，漏了 $ 反而"通过"， 把自己误导了 —— 单测要直接 import 生产函数，别手抄。

A.2 标的池事故：9[0-9]{5} 误杀北交所

用 9[0-9]{5} 当黑名单，意图是拦 B 股，实际把 920xxx 北交所 308 只全杀了。

  • 9* 段实测 308 只全是 920xxx，B 股 0 只；
  • B 股的真实段位只有 900xxx；
  • 修复后命中数：C1 90→92、C2 47→46、双共振 20→19。

教训：黑名单要先用数据验证它拦的是什么，别无脑照抄。

A.3 ETF 霸榜

债券 ETF 特性（净值曲线平滑、做市商高频对倒、面值附近盘整）完美命中 「温和上涨 + 高换手 + 高获利筹码」。修正：标的池过滤，两处都要加 （fetch_all.js 落盘前 + screen.js 建池时）。

教训：stockdb 的 日k 表是「所有场内证券」的混合表。 任何全市场策略的第一步都必须是标的池过滤。

A.4 筹码恒 100%

无衰减的成交量加权，在单边上涨的票上恒等于 100%（90 天里每天均价都低于今天收盘价）。

教训：任何"占比类"指标都要检查是否在某些形态下退化为常数。退化 = 无信息量。

A.5 银行股排第一

洗盘形态五维（振幅收敛 / 缩量 / 均线粘合 / 位置 / 量能抬头）恰好奖励了"不波动"的票。 银行股振幅小、缩量、均线贴合 → 形态分很高，但银行不可能"主力洗盘即将拉升"。

修正：共振数设为排序主键。

教训：多指标加权打分前，先想清楚"什么情况必须排前面"，把它设成主键， 而不是指望权重调参。纯加权模型容易被"某一维度极端高分"的样本劫持。

A.6 维度饱和：写了 30% 权重，实际贡献 1%

见 §6.8。这是最隐蔽的一类问题 —— 流程全通、结果非空、参数也配了， 只有把分布量出来才会发现某个维度全员满分。

教训：权重是声明，方差贡献才是事实。 交付前必须量。

A.7 字段名事故：自检查不出的 bug

页面按 r.c 取收盘价，但 7899 返回的是 close → 图表显示 undefined， 而 node --check 与 selftest.js 全绿。

教训：静态检查查不出运行时字段名错。图表类改动必须截图验真。

A.8 自检本身也会误报

页面重做后自检报「缺少 #xxx」10 处，全部是测试自身的假设（旧 DOM id、 旧前缀循环写法），不是页面缺陷。

教训：报"缺少 #xxx"先判断是不是真的缺，改自检的判定条件， 不要为了过测把页面改回旧结构。但改完要同时跑旧页面确认无回归。

A.9 别把公式硬编码进自检

自检第 10 组原本写死 deep*0.40 + shrink*0.22 + …。 换策略族后权重变了 → 必然假失败。

修法：读 meta.scoring.weights 反算。
