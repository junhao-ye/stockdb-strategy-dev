# scripts/ 契约

Node 脚本零第三方依赖，仅用 Node 内置模块（`http`/`fs`/`path`）。建议 Node ≥ 18。
Python 脚本用标准库 + `stock_sdk`（`pybao/`）。

## 执行顺序

```
fetch_all.js  （或 fetch_all.py，产出逐条一致）
                    ↓
            _cache/kline.json + _cache/_calendar.json
                    ↓
              screen.js → result.json + result.json.js
                    ↓
        ┌───────────┴───────────┐
   make_report.js          build_dashboard.template.html
        ↓                         ↓
  筛选结果报告.md             策略看板.html
                                  ↓
                            selftest.js（校验页面与引擎一致）
```

## fetch_all.js

全市场日K批量取数器。**代码前缀 × 日期区间**，4 个请求取回全市场整段历史
（官方 Python 接口文档 §13.2 的推荐写法，见 SKILL.md §2）。

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `BASE` | `http://127.0.0.1:7899` | 服务地址 |
| `OUT` | `./_cache` | 输出目录 |
| `DAYS` | `130` | 取的交易日数（条件三需 ≥100） |
| `CAL_CODE` | `000001` | 用哪只票推导交易日历 |
| `PREFIXES` | `0*,3*,6*,920*` | 股票段前缀。去掉 `920*` 即排除北交所 |

**输出**：`<OUT>/kline.json`（`{code: [{d,c,pc,o,h,l,v,a,to,p,am,st,fsh,fmv,n}]}`）、`<OUT>/_calendar.json`

**性能**：4 请求 / **约 7 秒** / 71.3 万条记录 / 股票池 5494 只（含北交所 308）。

**为什么用前缀而不是 `all:`**：`1*`/`5*`（基金/债券/ETF）不在股票段前缀内，
池子天然干净，**无需事后正则过滤**。

**退出码**：`3` = 读不到交易日历（7899 未就绪）；`1` = 股票池为空。

> ⚠ **不要在前缀黑名单里写 `9[0-9]{5}`** —— 那会误杀 920xxx 北交所（实测 308 只）。
> B 股只有 `900xxx`。见 SKILL.md §3。

## fetch_all.py

与 `fetch_all.js` **等价的 Python SDK 版**（走 `stock_sdk.rd`）。产出经实测**逐条一致**
（5494 只 / 712,772 条 / 0 差异）。

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `PYBAO` | — | `pybao/` 目录绝对路径（或改用 `PYTHONPATH`） |
| `OUT` / `DAYS` / `CAL_CODE` / `PREFIXES` | 同 js 版 | 同上 |

**前置**：`pybao` 需可导入 —— 设 `PYBAO` 或 `PYTHONPATH`（推荐），或跑一次 `pybao/安装.py`。
**退出码**：`2` = 无法导入 `stock_sdk`；`3` = 无交易日历；`1` = 股票池为空。

> Python 的 `QueryResult` 要用 **`.do()`** 取 `list[dict]`；`.vals()` 只给**无字段名的数组**。
> 详见 `references/protocol.md`。

## screen.js

筛选引擎模板。**改 CFG 与条件段，不要改骨架。**

> ⚠ **本文件自带一套「三条件·洗盘拉升」示例策略作为默认值（`cond1`/`cond2`/`cond3`）。**
> 那只是**样例**，不是技能在推行这个策略。
> **换策略时的正确做法：把 `screen.js` 复制到你的项目目录再改**（别原地改技能文件），
> 并把三个条件段整段替换掉。骨架（取数除外）才是复用价值所在：
> 标的池过滤、筹码近似、评分框架、输出契约、漏斗计数。
> 换策略族（如洗盘 → 超跌反转）**必须先读 `references/strategy-variants.md`** 重标评分，
> 不可照抄示例的维度与权重。

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `CACHE` | `./_cache/kline.json` | 输入 |
| `OUTDIR` | 脚本所在目录 | 输出目录 |

`CFG` 参数含义见 `references/screening-cookbook.md` §7。

**输出**：`result.json`（完整）、`result.json.js`（`window.STRATEGY_RESULT=...`，页面离线加载）

**退出码**：`2` = 找不到输入缓存。

## make_report.js

由 `result.json` 生成 `筛选结果报告.md`。无参数（读 `OUTDIR`）。

> ⚠ 报告标题与小节文案**内含「洗盘」字样**，换策略后需一并改。
> 数据读取部分是通用的（`result.json` 的字段契约见本文件顶部流程图下游说明）。

## selftest.js

页面与引擎一致性自检。**不依赖浏览器**。

```
node selftest.js                    # 校验目录内**全部**含 STRATEGY_RESULT 的页面
node selftest.js 策略工作台.html      # 只校验指定页面
```

检查 10 组：DOM 契约 / 资源引用 / 协议用法 / 口径一致性 / 结果集字段 /
排序单调性 / 条件口径回归 / 标的池纯度 / **板块覆盖（防误杀回归）** / 评分分解自洽。

**设计无关**（重要）：页面骨架可自由重做，自检不会因此误报。判定方式是
「多选一」而非写死 ID：

| 结构 | 表格式 | 工作台式 | 矩阵式 |
|---|---|---|---|
| 结果容器 | `#tb`（表格体） | `#list`（卡片列） | `#matrix` + `#mBody` |
| 详情容器 | `#draw` + `#mask`（遮罩抽屉） | `#main`（常驻面板） | `#sheet`（底部浮层） |
| 必备 | `STRATEGY_RESULT`、重算入口、漏斗消费 —— 三者任一写法均可 | 同 | 同 |

其它版式无关点：

- **计数容器** 认 `#funnel` / `#cnt` / `#c1` 任一。
- **纯离线页跳过第 3 组**（协议用法）：页里没有 `qz:` 即视为不做实时重算，
  不强制它处理配额提示 —— 别为了过测给离线页硬塞一段假重算。
- **第 4 组口径一致性**：页面没复刻的 CFG 项**直接跳过**（如矩阵页不做实时重算）。
  取值时忽略 `: 0` 形式的默认兜底（否则会撞上 `p.wShrink || 0` 这类写法误报）。
- **第 10 组评分分解**：**读 `meta.scoring.weights` 反算**，不硬编码公式。
  ⚠ 别把 `deep*0.40 + shrink*0.22 + …` 写进自检 —— 换策略族后必然假失败。
  已作主排序键、不计入评分的因子（如 dev120）不会出现在 `scoreParts` 里，属正常。

> 若你重做页面后自检报「缺少 #xxx」，**先判断是不是真的缺** ——
> 如果你换了交互范式（如抽屉改常驻面板），改自检的判定条件，不要为了过测把
> 页面改回旧结构。改完请**同时跑旧页面**确认没有回归。

第 9 组会读 `_cache/kline.json` 核对池构成，**专门防止「某板块被过滤规则整段误杀」**
（如 §3 记录的 `9[0-9]{5}` 误杀北交所事故）。无缓存时该项跳过。

> ⚠ **自检不是万能的**：它只做静态文本匹配，**查不出运行时字段名错误**。
> 实测事故：页面把 `r.c` 当收盘价，但 7899 返回的是 `close` → 图表静默显示
> `undefined`，而 `node --check` 与自检**全绿**。图表类改动务必再用无头浏览器
> 截图确认（见 `references/protocol.md` §2.4）。

**退出码**：`0` = 全通过；`1` = 有失败项；`2` = 找不到页面。
**CI/交付前必须为 0。**

## build_dashboard.template.html

非可执行资产。复制为 `策略看板.html` 后按需改标题、列、筛选器。

**依赖**：同目录的 `result.json.js`。两者一起拷走即可离线使用。

## 失败兜底

| 情况 | 处置 |
|---|---|
| 7899 未启动 | `fetch_all.js` 退出码 3；页面仍可开（离线结果集），状态灯转灰 |
| 单日请求连续超时 | 重试 3 次后跳过，`errs` +1；完成后检查 errs 是否恒为 0 |
| 返回值含「测试期超2000次」 | 误用了**在线接口**，改回 `rd` 通道（SKILL.md §2.2） |
| 数据未更新到最新交易日 | 先跑 `数据更新.exe`；或在脚本里按 `keys` 表末位取实际最新日 |
| 结果全空 | 先查标的池是否过滤过头，再查阈值是否过严 |
| `selftest.js` 报口径不一致 | 页面 `runScreen()` 与 `screen.js` 的 CFG 参数被改岔了，对齐参数 |
