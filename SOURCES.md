## 2. 决策记录

| 决策                                        | 状态                         | 依据                                                                                              |
| ----------------------------------------- | -------------------------- | ----------------------------------------------------------------------------------------------- |
| 技能类别 = `integration-documentation`        | adopted                    | 主体是专有数据库的协议与用法；需 API 面 / 配置 / 用例 / 已知问题 / 版本差异五维                                                |
| 执行形态 = `script-backed-workflow`           | adopted                    | 协议易错、筹码计算脆弱，必须固化为可执行脚本                                                                          |
| 拒绝 `inline-guidance`                      | rejected                   | 协议 + 坑 + 算法 + 页面四块内容量超出单文件可扫描范围                                                                 |
| 拒绝 `reference-backed-expert` 为**唯一**形态    | rejected                   | 纯文档无法防止取数代码被重写错；必须有脚本兜底                                                                         |
| 拒绝 `router`                               | rejected                   | 无「不同输入走不同下游」的需求，只有一个主流程                                                                         |
| 拒绝 `subagent-fork` / `hook-backed`        | rejected                   | 无可强制执行的确定性约束，也无需隔离上下文                                                                           |
| **取数走裸 HTTP 而非 `gp.js`**                  | adopted                    | S12：`gp.js` 在 Node 下抛 `SDK校验失败`；裸 HTTP 无门禁、字段一致。S16 补充：Python SDK 亦无门禁                          |
| **必须过滤标的池**                               | adopted                    | S12：不过滤则债券 ETF 霸榜（累涨 0.04% 却命中全部条件）                                                             |
| **筹码加时间衰减**                               | adopted                    | S12：不衰减则单边上涨股恒 100%，排序无区分度                                                                      |
| **共振数作排序主键**                              | adopted                    | S12：纯加权会被"不波动"的银行股劫持                                                                            |
| **零共振要解释而非放宽**                            | adopted                    | S13 + S6：不同条件刻画不同阶段，互斥是策略特性                                                                     |
| **取数改用 `k1=all:` 每交易日一请求**                | superseded                 | S16：全市场单日一次可取 7490 条 / 0.2s；130 请求取代 19,500 请求                                                  |
| **取数最终改用「前缀 × 日期区间」**                     | **superseded S16 的 v2 方案** | S18 §13.2 官方推荐写法 + 实测：**4 请求 / 7.2s / 71.3 万条**，且池天然纯股票                                         |
| **修 `9[0-9]{5}` 误杀北交所**                   | **corrected（真 bug）**       | S18 + 实测：`9*` 段 308 只**全是 920xxx**、B 股 0 只；旧正则与「北交所保留」政策自相矛盾。修复后命中数 C1 90→92、C2 47→46、双共振 20→19 |
| **策略取数只用 `rd` 通道**                        | adopted                    | S16：`get_*`/因子/财务/资金流均走**在线接口**且有配额                                                             |
| **补用 `zb` / `bk` / `rd.get_data` 三个本地接口** | adopted                    | S18：均为本地能力，可替代手写复权、周月K合成、MACD/KDJ/RSI/BOLL/MA                                                   |
| **补录服务端参数 `num`（切片）/ `ap`（投影）**           | adopted                    | S18 §6.2/6.3 + 实测 `.url()` 反查                                                                   |
| **补录私有存储规范**                              | adopted                    | S18 §14/§15：必须写 `./mydb`，禁自建 SQLite/DuckDB，批量必须 `pipe.mset`                                     |
| 保留 Python SDK 版取数器                        | adopted                    | S17：用户明确要求；`rd` 通道与裸 HTTP 同数据，`.url()` 是学语法的利器                                                  |
| 不把 MCP 作为批量取数主路径                          | adopted                    | S16 + S18：MCP 41 个工具多数包在线接口，配额受限；批量仍走 `rd`                                                      |
| 分钟级数据不纳入脚本                                | deferred                   | S6 明确警告暴力拉取会永久封禁设备                                                                              |
| 真实筹码分布不外接                                 | deferred                   | 全市场近似的量级（5 万次 / 0.1 秒）外接接口无法满足；需要精确时另行外接                                                        |
| `references/evidence/` 留空                 | deferred                   | 尚无用户反馈的误判案例积累                                                                                   |

## 5. 检索停止理由

进一步检索当前低收益：

- 官方四种通道（HTTP / Python / MCP / Excel）的入口与用法均已定位并写入 `protocol.md` §7
- 三个取数坑已通过 ~40 组参数排列实测确认边界，无法通过继续试错获得新信息
- 五维覆盖矩阵无空缺
- 唯一已知空白（真实筹码分布）已明确标注为需外接，属**范围外**而非检索不足
