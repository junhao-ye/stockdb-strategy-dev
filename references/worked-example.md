## 1. 需求

> 三个条件找「主力洗盘后即将拉升」的股票：
> 1. 连续 3 日上涨、不超过 7% 涨幅、获利筹码 70% 以上
> 2. 2 日换手率前 100 名、获利筹码 70% 以上
> 3. 90 个交易日内 3 次涨停、上市天数 > 30 天、获利筹码 80% 以上、ST 除外

用户选择：筹码用**成交量加权近似**；交付**结果 + 页面**两者都要。

## 2. 端到端流程

```bash
# 0) 环境探测
curl -s "http://127.0.0.1:7899/?cmd=get&t=%E6%97%A5k%3A000001%3A20260930&json=1"
#    → {"date":20260930,"code":"000001","name":"平安银行",...}   服务在线

# 1) 取数（DAYS=130 因条件三需 90 日窗口 + 缓冲）
DAYS=130 node fetch_all.js
#    [池] 全部 7563 / 退市 340 / 股票池 5184
#    [历] 共 6321 天, 取近 130 天: 20260325 ~ 20260930
#    [任务] 130 日 × 104 片 = 13520 请求, 并发 6
#    [完] 落盘 5184 只 / 记录 972846 条 / 错 0 / 耗时 11.0s

# 2) 筛选
node screen.js
#    [条件1] 90 只 / [条件2] 47 只 / [条件3] 104 只
#    [共振] 命中≥1: 221 只, ≥2: 20 只
#    分层: 三条件 0 / 双条件 20 / 单条件 201

# 3) 报告 + 页面
node make_report.js
cp scripts/build_dashboard.template.html 策略看板.html

# 4) 自检
node selftest.js      # 51 通过 / 0 失败
```

> ⚠ **上面第 1 步的日志是 v1 时代的（`130 日 × 104 片 = 13520 请求`）。**
> 取数器已升级到 **v3 前缀 × 日期区间 = 4 请求 / 约 7 秒**，日志长这样：
> ```
> [任务] 4 个前缀 × 1 次区间请求 = 4 请求（区间 20260325<20260930）
>  0*       193204 条  2.1s
>  3*        ...
> [完] 抓到 5494 只 → 保留 5494 只（含北交所 308 只）/ 记录 713338 条 / 错 0 / 耗时 7.2s
> ```
> 命令本身没变（还是 `DAYS=130 node fetch_all.js`），变的只是内部实现。
> **不要照抄旧日志里的分片数字去做性能估算。** 详见 `SKILL.md` §2.1。

## 4. 坑 1：ETF 霸榜（最严重）

### 反例（首版输出）

```
══════ 条件1 TOP12 ══════
  159112 科创债ETF银华   收102.58   筹码100   累涨0.04%
  159113 科创债ETF大成   收102.585  筹码100   累涨0.05%
  159116 科创债ETF工银   收102.764  筹码100   累涨0.05%
  159395 信用债ETF大成   收103.888  筹码100   累涨0.05%
  ...
══════ 条件2 TOP12 ══════
  520510 港股通医疗ETF华夏  收1.027  筹码100  2日换手376.41% (#1)
  513930 恒生生物科技ETF   收1.115  筹码100  2日换手294.25% (#3)
```

### 诊断

债券 ETF 的特性完美命中「温和上涨 + 高换手 + 高获利筹码」：
净值曲线平滑（每日涨 0.04%）、做市商高频对倒（换手 300%+）、面值附近盘整（筹码 100%）。
**它们不是股票，不该进池。**

### 修正

```js
// 剔除 ETF/LOF/REIT/可转债/B股/逆回购（完整白名单见 SKILL.md §3）
const isStock = (code, name) =>
  !/^(159|16[0-9]|18[0-9]|50[0-9]|51[0-9]|52[0-9]|55[0-9]|56[0-9]|58[0-9]
     |11[0-9]|12[0-9]|204|900)/.test(code) &&
  !/ETF|LOF|REIT|基金|转债|债/i.test(name || '');
```

> ⚠ **注意上面这段与历史版本有一处不同。** 当时的写法末尾还有一段 `|9[0-9]{5}`，
> 那是**错的** —— `9*` 段实测 308 只**全是 920xxx 北交所**、B 股 0 只，
> 加了它会**整段误杀北交所**。已改为只拦 `900`（B 股的真实段位）。
> **不要从旧记录里把那一段抄回来。** 详见 `SKILL.md` §3。

**两处都要加**：`fetch_all.js` 落盘前（拿不到名称时按代码段）+ `screen.js` 建池时（有名称可二次校验）。
修正后：7545 只 → **5184 只股票池**，结果全部是正常个股。

### 教训

stockdb 的 `日k` 表是「所有场内证券」的混合表。**任何全市场策略的第一步都必须是标的池过滤**，
这一步不写，后面所有参数调优都是白费。

## 5. 坑 2：筹码恒 100%

### 反例

修正 ETF 后，条件一里大量结果仍是：

```
  600064 南京高科   筹码100   累涨5.51%
  600901 江苏金租   筹码100   累涨2.21%
  601328 交通银行   筹码100   累涨2.51%
  601398 工商银行   筹码100   累涨1.85%
```

### 诊断

无衰减的成交量加权，在**单边上涨**的票上恒等于 100%——
因为 90 天里每天的均价都低于今天的收盘价，分子 = 分母。

### 修正

加入**时间衰减**（近期成交权重更高，久远的视为已被换手消化）：

```js
const age = end - i;                              // 0 = 最新
const decay = 1 - (age / span) * 0.6;             // 最老保留 40% 权重
const v = (r.v || 0) * decay;
```

修正后同一批票：南京高科 100→100、江苏金租 100→100（确实在低位盘整，合理），
而工行/中行降到 96~98 —— **区分度出来了**，条件一的排序不再千篇一律。

### 教训

任何"占比类"指标都要检查**是否在某些形态下退化为常数**。退化 = 无信息量。
做一次分布直方图或看看极值占比，就能发现。

## 6. 坑 3：银行股排第一

### 反例

修正前两项后，综合分榜首是：

```
  000088 盐 田 港  分125  [C1] 筹码100 洗盘80
  600018 上港集团  分111  [C1] 筹码85.9 洗盘71
  601939 建设银行  分106  [C1] 筹码98.2 洗盘62
  601398 工商银行  分104  [C1] 筹码100 洗盘60
```

### 诊断

洗盘形态的五维（振幅收敛 / 缩量 / 均线粘合 / 位置 / 量能抬头）
**恰好奖励了"不波动"的票**：银行股振幅小、缩量、均线贴合，形态分很高。
但银行股不可能是"主力洗盘即将拉升"——它们是权重蓝筹，没有主力控盘逻辑。

### 修正

**把共振数设为排序主键**：

```js
combined.sort((a,b) => b.tags.length - a.tags.length || b.score - a.score);
//                      ↑ 主键：命中条件数          ↑ 次键：综合分
```

修正后榜首变成 `603391 力聚热能`(C1+C2) / `002866 传艺科技`(C2+C3) —— 双共振的中小市值票。

### 教训

**多指标加权打分前，先想清楚"什么情况必须排前面"**，把它设成主键而不是指望权重调参。
纯加权模型容易被"某一维度极端高分"的样本劫持。

## 7. 可复用的判断

| 判断 | 依据 |
|---|---|
| 三条件零共振要解释而非放宽 | 高换手与温和连涨天然互斥，是策略特性 |
| 双共振（20 只）是实战重点 | 同时具备两种洗盘特征 |
| 全市场近似计算放本地 | 5 万次近似 0.1 秒；外接接口做不到这个量级 |
| 精确筹码只在局部需要时外接 | 粗筛用近似、精研用外接，分工明确 |
| 交付必须含页面 + 结果 | 用户明确要"两者都要"；页面提供下钻，报告提供全局 |
