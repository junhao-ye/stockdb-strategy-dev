## 1. 为什么不能照抄

`SKILL.md` §5.2/§5.3 的维度与权重是为**「主力洗盘 · 拉升前夜」**这一个假设标定的。
换一个策略族时，**有些维度方向直接相反**——照抄会让模型奖励错误的东西。

最典型的反例：

| 维度 | 洗盘拉升策略 | 超跌反转策略 |
|---|---|---|
| 均线状态 | **要粘合**（26 分，MA5/10/20 离散度 <5% 得分） | **剔除粘合**（离散度 <5% 直接淘汰） |
| 换手率 | **要活跃**（活跃度×10%，越高越分） | **要死寂**（低换手×12%，0% 才满分） |
| 位置 | 90 日区间 **25~75 分位**（中位最佳） | **越低越好**（要求破 MA120 达 10%+） |
| 量能 | 要**抬头**（最新量/前5日均量 >1.05） | 要**创新低**（≤20 日最小量） |

**结论：策略族一换，"什么算好"就翻转了。重标定是重新设计，不是调参数。**

## 2. 策略族分类与方向表

先判定目标策略属于哪一族，再按方向选维度。

| 策略族 | 收益来源 | 价的位置 | 量 | 均线 | 换手 | 典型信号 |
|---|---|---|---|---|---|---|
| **洗盘拉升** | 主力洗盘结束启动 | 区间中位（25~75） | 缩量后抬头 | **粘合** | 活跃 | 温和连涨、高换手、涨停基因 |
| **超跌反转** | 向均值回归 | **远低于**长均线 | **创新低** | **发散**（远离） | **死寂** | 破 MA120 深、量枯竭 |
| **趋势跟随** | 趋势延续 | 创新高 / 站上均线 | 温和放量 | **多头排列、发散** | 适中 | MA5>MA10>MA20>MA60 |
| **突破** | 平台突破 | 逼近前高 | **显著放量** | 由粘合转发散 | 骤升 | 箱体上沿 + 2× 量 |
| **回调买点** | 强势股回调结束 | 靠近均线支撑 | 缩量回调 | 多头未破 | 衰减 | 回踩 MA20 不破 + 缩量 |

**方向互斥必须显式处理**：同一维度在两个族里可能要求完全相反，不能靠"权重调小"来兼容，
**必须换掉该维度的计分函数（或直接改成排除条件）**。

## 3. 重标定四步法

### 第 1 步：写清「收益来源」一句话

不能是"找好股票"。要具体到机制，例如：
- 洗盘拉升：「主力已控盘、洗盘充分、即将脱离成本区」
- 超跌反转：「抛压枯竭、价格远离长期均值，存在回归动能」

**这句话决定后面所有维度的正负号。**

### 第 2 步：把每个维度定成「越大越好」或「越小越好」

| 维度 | 超跌反转的方向 | 计分（越靠近满分越好） |
|---|---|---|
| 超跌深度 | 越大越好（离 MA120 越远） | 折价 10% → 0 分；50% → 100 分 |
| 缩量程度 | 越大越好（量比越小） | 量比 1.0 → 0 分；≤0.5 → 100 分 |
| 低于 MA60 | 越大越好 | 等于 MA60 → 0 分；低于 30% → 100 分 |
| 低换手 | 越大越好 | 换手 ≥3% → 0 分；0% → 100 分 |
| 止损空间 | 越大越好 | 距止损 ≥20% → 100 分 |

统一成"越大越好"后，加权求和才有意义（否则正负维度会互相抵消）。

### 第 3 步：只设「单侧阈值 + 线性映射」

每个维度给一个 `零分点` 和一个 `满分点`，中间线性插值，两端 `clamp(0,100)`：

```js
const clamp = v => Math.max(0, Math.min(100, v));
const linear = (v, zeroAt, fullAt) => clamp((v - zeroAt) / (fullAt - zeroAt) * 100);

// 例：缩量（量比 1.0 得 0 分，0.5 得满分）
const shrink = linear(1 - volRatio20, 0, 0.5);
```

**不要用多段阈值**：分档会制造人为断点，同一只票差 0.01 就掉档，排序出现跳变。

### 第 4 步：权重按「收益来源的因果距离」分配

**离收益来源越近的维度，权重越高。**

超跌反转的收益来源是「均值回归」，所以：
- **超跌深度 40%** ← 决定回归空间，最直接
- 缩量程度 22% ← 抛压枯竭的直接证据
- 低于 MA60 18% ← 反弹尚未展开
- 低换手 12% ← 辅助（无人抢跑）
- 止损空间 8% ← 风控辅助，不产生收益

若把「止损空间」设成 30%，模型会专挑"跌得浅但止损远"的票，**与策略意图背离**。

## 4. 实例：超跌缩量·均值回归（完整参数）

> 出处：本技能实测项目 `oversold-rebound-strategy/`，2026-09-30 数据，
> 全市场 5494 只 → 策略池 4579 只 → **命中 93 只**。

### 入场条件

| # | 条件 | 参数 |
|---|---|---|
| 1 | 成交量创 20 日新低 | `volLowWin = 20`，`lastV <= min(近20日V)` |
| 2 | 低于 MA120 达 10% 以上 | `maLong = 120`，`discountMin = 10` |
| 3 | 非 ST | 双验证 |
| 4 | 仅主板/创业板 | 排除 688/689/920 |
| 5 | 现价 ≤ MA60×1.1 | `maMid = 60`，`maMidRatioMax = 1.10` |
| 6 | 流通市值 > 20 亿 | `minFmv = 20e8` |
| 7 | 上市 > 90 天 | `minListDays = 90` |
| — | `minRecords = 130` | **MA120 需 ≥120 条 + 余量**；取数 `DAYS=200` |

### 排除条件

| # | 条件 | 参数 | 实测剔除 |
|---|---|---|---|
| 1 | 获利盘 > 70% | `maxProfitChip = 70` | **0 只（未生效）** |
| 2 | 筹码高度集中 | `maxConcPct = 0.90`（**候选池 90 分位**） | 31 只 |
| 3 | 均线黏合 | `maxMaSpread = 0.05` | 218 只 |
| 4 | 站上 MA60 | `close >= MA60` | 13 只 |

### 评分

> **本实例的评分模型经历过一次重标，这里给的是最终版。**
> 初版是五维（超跌深度40 / 缩量22 / 低于MA60 18 / 低换手12 / 止损空间8），
> 后来用户明确指定了三维权重，并借此发现了「**维度饱和**」问题（见 §4.1）。
> 两版都保留在此，因为初版的**推导过程**（§3 四步法）比结论更有参考价值。

```
综合分 = 缩量×40 + 箱体低位×30 + 获利盘×30        ← 最终版（用户指定权重）
排序主键 = close/MA120 升序                        ← 用户指定，与综合分分离
```

| 维度 | 权重 | 计分 |
|---|---|---|
| 缩量 | 40% | 量比 ≤ **池内 25 分位** 满分、≥ 75 分位 得 0 |
| 箱体低位 | 30% | `(现价 − 近60日最低) / (近60日最高 − 最低)`，0=贴底；得分 `(1−位置)×100` |
| 获利盘 | 30% | ≤ **池内 25 分位** 满分、≥ 90 分位 得 0 |

⚠ **锚点取分位而非绝对值**，这是本实例最重要的修正 —— 原因见下节。

### 4.1 维度饱和：写了权重却没在打分

初版用绝对锚点（量比 ≤0.5 满分、获利盘 ≤20% 满分），实测 93 只命中：

| 维度 | 满分占比 | 对总分的方差贡献 |
|---|---|---|
| 缩量 40% | 71.0% | 62.3% |
| 箱体低位 30% | 3.2% | 51.0% |
| 获利盘 30% | **92.5%** | **1.3%** ← 权重是摆设 |

**根因**：命中池是硬条件**筛窄后的子集**。条件含「量创 20 日新低」→ 池内量比天然普遍 <0.5；
含「深度破 MA120」→ 池内获利盘天然普遍很低。**在窄池里用"看起来正常"的绝对锚点必然饱和。**

改**候选池分位锚点**后：满分占比 41.9% / 3.2% / 25.8%，方差贡献 77% / 5% / 29%，
**总分极差 28.8 → 82.8 分**。判据与做法见 `SKILL.md` §5.5。

### 交易计划

```
持仓 10-20 个交易日
回踩低点 = 近 20 日最低价（pullbackWin = 20）
止损价   = 回踩低点 × (1 - 3%)
```

### 漏斗实测（可直接当量级参照）

```
策略池（非ST主板/创业板）   4579
  ≥130日 且 非ST            4385   −194
  上市 > 90 天               4385   −0     ← 冗余：≥130日已含 >90天
  流通市值 > 20 亿           4043   −342
  成交量创 20 日新低          738   −3305  ← 最紧的一条
  低于 MA120 ≥10%            319   −419
  现价 ≤ MA60×1.1            318   −1     ← 近乎冗余
  排除条件后                  93   −225
```

> **注意两条冗余条件**：「上市>90天」（被 ≥130日包含）与「现价≤MA60×1.1」
> （只剔 1 只）。它们不是错的，但**报告里要如实呈现每步淘汰数**，
> 让用户看到哪条在起作用、哪条是摆设。

## 5. 排除条件的「静默失效」检查

**这是最容易骗过自己的地方**：流程跑通、有结果输出、参数也配了，
但那条排除条件一只都没剔掉。

### 必做动作

```js
// 每个排除条件都记数，跑完打印
const rejCnt = {};
for (const r of rejected) for (const x of r.reasons) rejCnt[x] = (rejCnt[x]||0) + 1;
console.log(Object.entries(rejCnt).map(([k,v]) => `${k}×${v}`).join(' / '));
```

### 判别表

| 现象 | 判断 | 处置 |
|---|---|---|
| 剔除数 = 0 | 阈值与候选池分布**完全不重叠** | 该条件对本策略族不适用，**标注「未生效」**，不要硬调 |
| 剔除数 = 候选池 nearly全部 | 阈值过松 | 改分位法重定阈值 |
| 剔除数 = 1~2 | 阈值落在分布极端尾部 | 改用**分位法**（如 90 分位） |
| 剔除数 ≈ 候选池的 10~30% | 健康 | 保留 |

### 为什么不许"偷偷放宽阈值凑数"

用户给了「剔除获利盘 > 70%」，若实测一只不剔，就把它改成 30% 让它剔掉 45 只，
**用户会以为自己要的那条条件在过滤，实际过滤逻辑已被换掉**。正确做法：

1. **阈值的原样保留**，报告/页面里写「本批未触发，原因：候选池获利盘中位 6.3%」；
2. 若判断用户真实意图是"排除获利盘高的票"，**在报告里提出改用分位法的建议，让用户确认**；
3. 只有用户确认后才改数。

## 6. 换族检查清单

- [ ] 写出「收益来源」一句话，并据此定每个维度的**正负号**
- [ ] 检查有没有维度**与上一族方向相反**（换手、均线状态是最常翻的两项）
- [ ] 所有维度统一成"越大越好"，再用 `clamp` + 线性映射计分
- [ ] 权重按「离收益来源的因果距离」分配，不要让风控项压过收益项
- [ ] `minRecords` ≥ 最长均线窗口 + 余量（用 MA120 ⇒ ≥130；取数 `DAYS` 再放宽）
- [ ] **每个排除条件都打印实际剔除数**，逐条过 §5 判别表
- [ ] σ 归一化类阈值取**当期分位**，不拍绝对值
- [ ] 失效/冗余条件在交付物里**如实标注**，不静默改造
- [ ] 排序主键与用户原话一致（若用户指定了排序，综合分只作参考列）
- [ ] `selftest.js` 的口径一致性组已同步新 CFG（否则页面与引擎会漂移）
