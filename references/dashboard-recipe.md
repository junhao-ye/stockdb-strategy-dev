## 1. 起手方式

```bash
cp scripts/build_dashboard.template.html 策略看板.html
# 把 screen.js 产出的 result.json.js 放在同目录（页面会离线加载它）
```

模板已含下述全部要素，**改而不写**：换标题、调列、加筛选器。

## 2. 页面骨架必须有的六块

**六块能力**（不是六块 DOM）。三种已验证的版式都能承载这六项能力，选哪种看你想让用户
"读一份单"、"坐在工作台上调参"，还是"同时看多个切面"：

| 能力 | 作用 | 缺失后果 |
|---|---|---|
| 条件卡（可点选） | 展示三条件命中数，点选过滤 | 用户无法按条件下钻 |
| 工具条（搜索/共振/市值/导出） | 快速收窄 | 结果多时无法定位 |
| 统计条 | 交易日/股票池/命中数/在线状态 | 不知道数据新旧 |
| 状态灯 | 探测 7899 在线与否 | 报错时不知是服务挂了还是没数据 |
| 结果浏览区（主表 **或** 卡片列表／散点图） | 结果浏览 | — |
| 单股下钻区（抽屉 **或** 常驻侧栏） | 单股下钻 | 无法判断"为什么它入选" |

### 三种版式（都实测通过）

| | A. 表 + 抽屉 | B. 工作台（三栏常驻） | C. 多视图矩阵 |
|---|---|---|---|
| 结构 | 顶部条件卡/工具条 + 宽主表 + 点行弹抽屉覆盖层 | 左控制台(≈268px) + 中散点+卡片列表(≈400px) + 右详情常驻 | 顶部 Tab 切 4 视图 + 工具条 + 底部滑出浮层 |
| DOM 锚点 | `#tb` `#th` `#draw` `#mask` | `#list` `#main` | `#matrix` `#mBody` `#sheet` |
| 适合 | 结果 50–500 条、以"读单"为主、要排序表格 | 结果 <200 条、要反复调参对比、要图形化看分布 | 想同时给多个切面 / 要向人解释"评分怎么来的" |
| 增量亮点 | 排序稳、列多不挤 | 散点（折价深度×缩量度，点大小=市值/颜色=获利盘档）、烛台图+MA60/MA120/止损线、筹码成本分布直方图、键盘导航(↑↓ / / Esc) | **评分构成堆叠条**、因子气泡图（箱位×量比，半径=分数/色=获利盘档）、小多图剖面网格、组合篮子+权重分配、底部浮层详情 |
| 详情形态 | 遮罩抽屉（覆盖） | 常驻右栏 | 底部浮层（`translateY(101%)` → `0`） |
| 代价 | 抽屉遮挡、不能边看详情边挑下一条 | 三栏在窄屏会挤，需 `min-width` 或媒体查询降级 | 视图多 → 代码量大，需统一 `render()` 调度避免重绘打架 |

**`selftest.js` 已做成版式无关**：结果区认 `#tb` **或** `#list` **或** `#matrix`，下钻区认
`#draw` **或** `#main` **或** `#sheet`；只有出现 `#tb` 时才要求 `#th`，出现 `#matrix` 时才
要求 `#mBody`。所以换版式不会误报失败——报"缺少 #xxx"时
**先判断是不是真的缺**，别为了过测把页面改回旧结构。
纯离线页（无 `qz:` 实时重算）会自动跳过第 3 组协议检查。

**离线兜底是硬要求**：默认加载 `./result.json.js` 注入的 `window.STRATEGY_RESULT`，
7899 没开也能看。这决定了页面是"报告"还是"只能当场跑的玩具"。
⚠ 路径写 `./result.json.js`（带 `./`）—— 自检按此字面匹配，且相对路径更稳。

**想再换版式**：起手别再从模板复制。先把上面六项能力列成清单，再自己决定 DOM 结构，
最后跑 `selftest.js` 确认识别得到（它会自动发现同目录所有含 `STRATEGY_RESULT` 的 html）。
单文件离线这条不能破——CSS/JS 全部内联，不引 CDN。

## 3. 取数写法（浏览器直连 7899）

```js
const BASE = 'http://127.0.0.1:7899';
const enc = encodeURIComponent;

async function httpJson(url) {
  const t = setTimeout(() => { throw new Error('超时'); }, 9000);
  const r = await fetch(url);
  const txt = await r.text();
  clearTimeout(t);
  try { return JSON.parse(txt); } catch (e) { throw new Error('返回非 JSON'); }
}

// 个股全历史 → 取末 90 条
const rows = await httpJson(`${BASE}/?cmd=vals&t=${enc('日k:' + code)}&json=1`);
```

### 浏览器直连的三条注意

| 注意 | 说明 |
|---|---|
| **必须是 `file://` 或同源托管** | `file://` 打开时请求 `127.0.0.1` 属跨源，但 7899 不校验 CORS 头 → 实测可用。若被浏览器拦截，起个静态服务托管 |
| **必须 `encodeURIComponent`** | `日k` 是中文，不编码在部分环境会坏 |
| **实时重算用前缀法** | 全市场重算 = **3 请求**（`qz:0` / `qz:3` / `qz:6` 各带一次日期区间）。⚠ 本文件旧版写的「全市场重算 = 19630 请求、务必 `CHUNK=50` + 并发 6」是 **v1 分片方案，已作废** —— 见 `SKILL.md` §2.1。务必给进度提示，否则用户以为卡死 |

实时重算的筛选逻辑**必须与 Node 引擎同口径**（模板里 `runScreen()` 就是这么写的，参数对照表见下）。
跑 `selftest.js` 第 4 项可自动校验两者一致。

## 4. 走势图（无依赖 SVG）

### 4.1 迷你走势（表内/卡片缩略图）

```js
function sparkline(rows, w = 900, h = 170) {
  const cl = rows.map(r => r.c);
  const mn = Math.min(...cl), mx = Math.max(...cl), pad = (mx - mn) * 0.08 || 0.01;
  const X = i => (i / (rows.length - 1)) * w;
  const Y = v => h - ((v - (mn - pad)) / ((mx + pad) - (mn - pad))) * h;
  const pts = cl.map((v, i) => `${X(i).toFixed(1)},${Y(v).toFixed(1)}`).join(' ');
  const up = cl[cl.length - 1] >= cl[0];
  const col = up ? '#ff4d4f' : '#3fb950';           // 涨红跌绿
  return `<svg viewBox="0 0 ${w} ${h}" preserveAspectRatio="none">
    <polygon points="0,${h} ${pts} ${w},${h}" fill="${col}" opacity="0.10"/>
    <polyline points="${pts}" fill="none" stroke="${col}" stroke-width="1.6"
              vector-effect="non-scaling-stroke"/>
  </svg>`;
}
```

**`vector-effect="non-scaling-stroke"` 别漏**——`preserveAspectRatio="none"` 会把线宽
横向拉伸成怪异粗细，加这个属性才正常。

### 4.2 烛台图 + 均线 + 止损线（详情区用）

工作台版式用烛台代替迷你线。要点：

| 要点 | 做法 |
|---|---|
| 坐标映射 | 先用整段 `high/low` 求 `mn/mx`，再加 6% padding；`X(i)` 按索引均分，**不要按日期均分**（停牌日会挤成一条缝） |
| 影线 + 实体 | 影线 `<line x1=xi x2=xi y1=Y(high) y2=Y(low)>`；实体 `<rect>`，高度 `Math.max(1, abs(Y(o)-Y(c)))`，**保证十字星也有 1px 可见** |
| 涨红跌绿 | 按 `c >= o` 判色，同 §6 |
| 均线 | `MA60`/`MA120` 各画一条 `polyline`，`fill:none` + 虚线区分 |
| 止损线 | 一条横向虚线 + 文字标注价格，颜色与"止损"语义一致（暖色） |
| 轴文字 | 只标首/末日期 + 最高/最低价，别每根都标 |

### 4.3 筹码成本分布直方图

把 `chipWindow`（如 90 日）内的成交量**加权**堆到价格轴上：

```js
// TP=(H+L+C)/3；越久远的量衰减越多（decay 0.6 → 最老一天权重 0.4）
const w = 1 - (age / WIN) * 0.6;
bins[binIndex(TP)] += vol * w;
```

- 分箱数 30–40（如 34），太多锯齿、太少糊成一团
- 当前价**左侧**的量 = 套牢盘，**右侧** = 获利盘，用两色区分
- 叠加两条竖线：现价、加权平均成本
- 这个图是"为什么它入选/为什么不入选"最有说服力的证据，**优先加**

## 5. 交互与筛选

| 交互 | 实现 |
|---|---|
| 表头排序 | 点击 `thead th` 切换 `sortKey` / `sortAsc`；数值与字符串分开比 |
| 行点击 → 抽屉 | `tr[data-code]` → 打开抽屉 → 拉 K 线 → 画图 |
| 条件卡过滤 | 点卡片切 `S.cond`，再 `render()` |
| 导出 CSV | 加 `\ufeff` BOM（否则 Excel 中文乱码）+ 正确转义引号/逗号/换行 |
| ESC 关抽屉 | `keydown` 监听 |
| 键盘导航（工作台） | ↑↓ 切上一只/下一只；`/` 聚焦搜索；Esc 清空。结果少时比鼠标快得多 |
| 散点选中 | 给每个 `<circle>` 挂 `data-code`，点击即选中同步列表 + 详情 |

**排序不要用默认字典序**：`"100" < "9"` 是字符串比较的经典坑。所有数值列显式 `Number()`。

## 6. 主题与配色

| 规则 | 做法 |
|---|---|
| **涨红跌绿** | 中国股市惯例；`#ff4d4f` / `#3fb950`。**不要用欧美配色** |
| 跟随宿主主题 | 深色环境用深底浅字；浅色环境反转（查 `IDE Theme`） |
| **颜色类不要写成抽象 class** | 内联 `style` 或显式 fill，否则某些渲染器回落成黑色 |
| 表头粘性 | `thead th { position: sticky; top: 0 }` + 容器 `overflow: auto` |
| 数字等宽 | `font-family: Consolas, monospace` 让数字对齐可读 |

## 7. 性能与边界

| 边界 | 处置 |
|---|---|
| 结果上万行 | 别一次全渲染；模板用「筛选后渲染」，必要时加虚拟滚动 |
| 抽屉反复开 | **缓存** `S.kline[code]`，第二次直接命中 |
| 7899 超时 | 9 秒兜底 + 明确错误文案（"请确认 stockdb.exe 正在运行"） |
| 停牌/无效价 | `close <= 0` 或 `volume <= 0` 的记录要过滤，勿当零值参与均线 |
| 汇总统计 | 对**完整结果**算，不能只算可见窗口 |
| 页面自足 | 一个 HTML + 一个 `result.json.js`，双击就能开，不依赖构建工具 |
| 三栏窄屏 | 工作台版式给容器 `min-width` 或媒体查询降级为纵向堆叠，否则 1280px 以下侧栏被压没 |
| **字段名别猜** | 7899 日k 返回**具名对象**（`date/open/high/low/close/volume/turnover/name`），不是 `{d,o,h,l,c,v}`。写 `r.c` 会静默变 `undefined` —— 用多键名兜底 `pickf(r,'c','close')`，并**截图验证** |

## 8. 评分维度体检（画图前先量一次）★

看板把评分**可视化**之后，用户会立刻看出哪个维度在划水。所以画图前先算两个数：

```js
// 满分占比：该维度有多少只拿了满分
const fullRate = rows.filter(r => r.scoreParts[k] === 100).length / rows.length;
// 方差贡献：该维度加权贡献占总分方差的比例
const share = varOf(rows.map(r => r.scoreParts['w' + K])) / varOf(rows.map(r => r.score));
```

| 判据 | 健康 | 危险 |
|---|---|---|
| 单维满分占比 | 20% ~ 45% | **> 70%** ⇒ 无区分度 |
| 单维方差贡献 | 与权重同量级 | **< 权重的 1/5** ⇒ 权重是摆设 |

命中池是被硬条件**筛窄过的子集**，绝对锚点极易饱和。实测：权重 40/30/30 的三维，
「获利盘」维度初版满分占比 92.5%、方差贡献仅 1.3% —— 写了 30% 权重实际没在打分。
改**候选池分位锚点**后：41.9% / 3.2% / 25.8%，方差贡献变为 77% / 5% / 29%，
总分极差 28.8 → 82.8 分。做法见 `SKILL.md` §5.5。

**可视化建议**：用**堆叠条**画三项加权贡献（`wShrink`/`wBox`/`wChip` 宽度相加 ≈ 总分），
比只显示一个总分数更能让人一眼看出「这只票靠什么得分 / 为什么没得分」。

**把锚点写进 `meta.scoring.anchors` 落盘**，页面读数即可，不用复刻分位算法；
`selftest.js` 第 10 组会**读 `meta.scoring.weights` 反算**校验分解自洽 ——
**别在自检里硬编码公式**，否则换策略族必出假失败。
