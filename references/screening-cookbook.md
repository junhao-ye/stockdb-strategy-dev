## 1. 数据前置

以 `_cache/kline.json` 为基础（`fetch_all.js` 产出）。每条记录字段：
`{d, c, pc, o, h, l, v, a, to, p, am, st, fsh, fmv, n}` = 日期/收/前收/开/高/低/量/额/换手/涨跌幅/振幅/ST/流通股本/流通市值/名称。

**窗口要够长**：条件三要 90 日涨停统计，筹码要 90 日分布，洗盘形态要 90 日位置——
**`DAYS=130` 是下限**。想做年线类条件（如 250 日均线）需 `DAYS=300`。

## 2. 筹码近似的正确用法

### 算法

```js
// 详见 screen.js 的 profitChip()
典型价 TP = (h+l+c)/3           // 当日成交均价代理
时间衰减 w = 1 - (日龄/窗口)×0.6  // 越久远越可能已被换手消化
权重    V = volume × w
获利筹码 = Σ{V | TP ≤ 现价} / ΣV × 100%
```

### 三条纪律

| 纪律 | 理由 |
|---|---|
| **必须加时间衰减** | 不加则单边上涨股恒 100%（银行/公用事业），排序失去区分度。`decay=0.6` 是实测甜点 |
| **必须标注为估算值** | 真实筹码需逐日换手衰减 + 股东账户数据，本地没有。写进页面和报告的注释里 |
| **只做同时点横向排序** | 不可跨时点比较，不可当绝对买卖阈值 |

### 何时该换真数据

局部需要精确筹码时，接 `a-stock-data` 技能的「筹码分布」端点（真实同价位换手叠加），
本技能的近似用于**全市场粗筛**——五万次近似计算在本地 0.1 秒完成，外接接口做不到。

## 3. 条件写法族

| 需求 | 写法要点 |
|---|---|
| 连续 N 日上涨 | `for i in [n-N, n)`: `close[i] > close[i-1]` **且** `pct_chg > 0`（双条件，防除权日误判） |
| 累计涨幅 | `(last.close - first.pre_close) / first.pre_close` —— **用首日 `pre_close`**，不是首日 `close`，否则少算第一天 |
| 温和上涨 | 在连涨序列中**排除涨停日**，否则「≤7%」形同虚设 |
| 缩量 | `近期均量 / 基准均量 < 1`；基准取 20 日 |
| 放量 | 同上 > 1（配合缩量做「缩量后放量」形态） |
| 均线粘合 | `(max(MA5,MA10,MA20) - min(...)) / MA20 < 阈值` |
| 位置分位 | `(现价 - 区间低) / (区间高 - 区间低)`；<0.25 低位，>0.75 高位 |
| 区间振幅带 | `(区间高 - 区间低) / 区间低` |
| 换手排名 | **先**全市场算和排序取前 N，**再**叠加其他条件。顺序反了会漏 |
| 新高/新低 | `close === Math.max(...window)` —— 注意用 `>=` 还是严格 `>` 会差一只 |
| 上市天数 | 窗口内记录数近似。**不要**拿首条记录日期当上市日（可能只是数据起始日） |

## 4. 涨停判定的三种口径

优先级从高到低：

```js
// ① 用 close/pre_close 反推（最可靠，能处理 ST）
pct = (close - pre_close) / pre_close * 100
涨停 = pct >= 阈值 - 容差

// ② 直接用 pct_chg 字段（省事，但除权日可能失真）
涨停 = pct_chg >= 阈值 - 容差

// ③ 名称/板块推断阈值
主板(60/000/001/002/003) 9.8% | 创业/科创(30/68) 19.5%
北交所(4/8/92) 29.5% | ST 4.7%
```

**容差 0.3%** 不是可选项——四舍五入和不同板块的实际涨停价会让「9.99%」偶尔小于 10%。
用 `is_st` **和**名称含 `ST` 双验证，历史记录里 `is_st` 偶有缺失。

## 5. 洗盘形态量化

```js
振幅收敛 22分  band = (max20-min20)/min20, 越小越高
缩量程度 22分  vShrink = avg5(vol) / avg20(vol), <1 得分
均线粘合 26分  maSpread = (max(MA5,10,20)-min)/MA20, <5% 得分
位置适中 18分  pos = 90日分位, 25~75 最佳（>75 = 派发不是洗盘）
量能抬头 12分  vRise = vol[-1] / avg5(vol[-6:-1]), >1.05 得分
```

总分 0~100。**「位置适中」区分洗盘与派发**：同样是均线粘合，出现在高位是出货、
出现在中位是洗盘。丢掉这个维度，模型会把高位横盘票当成机会。

## 6. 综合评分与排序

```
排序主键 = 共振数（3 > 2 > 1）
次排序键 = 洗盘形态×50% + 筹码集中度×25% + 获利筹码×15% + 换手活跃度×10%
```

### 为什么共振必须做主键

只按「洗盘形态 + 筹码」排，会得到反直觉的结果：**银行股排第一**。
原因——银行不波动，恰好「振幅收敛 / 缩量 / 均线粘合」全满分；筹码也恒高。
但银行不可能"主力洗盘即将拉升"。加上共振主键后，同时满足多条条件的票才会浮上来。

### 零共振不是 bug

不同条件刻画不同阶段：温和连涨 ↔ 高换手 ↔ 涨停基因，本就互斥。
**向用户解释，不要为了凑数放宽条件。** 遇到零共振时：
1. 报告双条件共振清单（通常 20 只上下）
2. 说明互斥原因
3. 让用户自行选一条条件深挖

## 7. 参数调优经验

| 参数 | 默认 | 调整方向 |
|---|---|---|
| `days`（连涨天数） | 3 | 加大→更严格，命中骤减 |
| `maxGain` | 7 | 「温和」的边界；>10 会混入强势股 |
| `minChip` | 70~80 | 70 是松筛，85+ 才是有区分度的紧筛 |
| `chipWindow` | 90 | 短窗反映近期成本，长窗反映长期套牢盘 |
| `decay` | 0.6 | 0=不衰减（不推荐），0.8=极重新近成交 |
| `topN`（换手） | 100 | 想更精可收到 50 |
| `lookback`（涨停统计） | 90 | 与 `DAYS` 联动，别超过可用数据 |

**调参副产品**：如果某条件恒命中 0 只或恒命中半个市场，多半是**单位错**
（把「手」当「股」、把百分数当小数）或**标的池没过滤**。先查这两项再去调阈值。
